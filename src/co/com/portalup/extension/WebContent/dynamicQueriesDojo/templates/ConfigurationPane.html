El feature Consultas dinámicas trabaja sobre un único repositorio: es el que muestra el panel y el único con el que se pueden diseñar y guardar consultas. Debe estar agregado a los escritorios donde se use.

Las consultas y los proyectos se guardan en el microservicio de DQ. Lo llama directamente el navegador del usuario, así que la URL debe ser accesible desde su equipo, usar https (la política de seguridad de ICN bloquea otras URL http) y permitir solicitudes CORS desde ICN.

*
Grupos de P8 del repositorio de las consultas, separados por punto y coma (nombre corto, nombre o DN). Solo sus miembros pueden abrir el feature.
Servicio que entrega en base64 el contenido de los documentos con las propiedades file_key y storage_name (en Resultados de consultas). Lo llama el servidor de ICN con ?storage_name=…&file_key=…; vacío: esos documentos no se pueden ver.
Servicio que junta en un PDF las páginas de los documentos con file_key_multivalue (versión 1). Es distinto del de descarga de arriba aunque comparta la URL base. Lo llama el servidor de ICN por POST con el token de Azure de abajo, y también descarga el PDF: el navegador no se conecta a estos servicios ni a S3.
Azure AD, flujo client_credentials. Con la URL de composición, el client ID, el secreto y el resource es obligatoria para ver los documentos con file_key_multivalue; el servidor de ICN guarda el token hasta que vence.
Pasado este tiempo se le avisa al usuario que el documento se sigue componiendo. Máximo 28: API Gateway corta las solicitudes a los ~29 s. Vacío: 10.
